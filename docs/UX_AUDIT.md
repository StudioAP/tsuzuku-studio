# 操作の往復の点検 — 2026-10-13

## Goal
写真を見たまま次の操作へ進み、選び直し・開き直し・戻りスクロールを減らす。

## Context
以前は選択写真の識別とライブプレビューを固定したが、連続操作の入口や前処理の確定操作がスクロール先に残っていた。375×667と320×700では下部メニューから前後移動ボタンが見えない。スマホ3サイズでは前処理の確定ボタンまで下がると写真が見えないことを合成デモで確認した。

## Constraints
写真を主役にするrepo DESIGN.mdを上位契約とし、global baseで補う。タップ対象の十分な大きさと明確な短いラベルは[AppleのButtonsガイド](https://developer.apple.com/design/human-interface-guidelines/buttons)も参照。新しい独自ジェスチャーを覚えずに操作できるよう、既存のドラッグ／ピンチとラベル付きボタンを使う。元写真・下書き・書き出しのモデルは維持する。

## 変更した代表経路

| 目的 | 以前の操作 | 改善後 |
|---|---|---|
| 下部の設定から次の写真へ | 上へスクロール → 次へ | 固定の「次へ」を1回 |
| 下部の設定から切り取りへ | 切り取り入口までスクロール → 開く | 固定の「切り取り・傾き」を1回 |
| 組写真の別写真を切り取る | 微調整を開く → 対象を選ぶ → 上へ戻る → 前処理を開く | 固定サムネイルで対象を選ぶ → 固定の切り取り入口 |
| 個別編集中に並べ替え | 編集を閉じる → 一覧の操作へ移動 → 並べ替え → 編集を開く | 「並び順を変える」を開く → 同じ位置のボタンで移動 |
| トリミングを確定する | 写真へ戻って確認 → 下へ戻る → 確定 | 写真を見ながら固定の確定ボタン |
| 別写真を同じ項目で調整する | 閉じた微調整を開き直す | 開いていた設定をそのまま使用 |

これは代表的なタップ・スクロール経路の比較であり、全操作やユーザー所要時間の計測ではない。

## Done when
5画面サイズで固定操作へ届き、連続並べ替えのボタン位置が変わらない。組写真の変形が混ざらず、前処理をキャンセルしても変更されず、適用した内容が元の編集に反映する。設定の展開状態と描画済みプレビューが維持される。既存の書き出し・下書き・オフライン等の検査も通る。

## Review / Retrospective
固定するものを「判断に必要な写真」と「次の操作」に絞り、詳細な設定だけをスクロールする。操作入口の位置だけでなく、設定の展開状態や切り取り中の領域サイズを保つことで、繰り返しの手順を減らす。合成デモとChromiumによる検査なので、iPhone Safari実機の指触りは別途確認する。
