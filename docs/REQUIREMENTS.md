# 要件定義 — つづく v1

更新日：2026-09-06。ユーザーとの会話で確定した範囲と、今回の実装上の判断を区別しています。

## 1. 目的と確定条件

iPhone内の写真を選び、横長写真を複数ページにつなぎながら、Instagramのカルーセル用画像を手軽に作る。SCRLにあるような「つながる投稿」を参考にするが、特定アプリのUI・資産・テンプレートは複製しない。

**ユーザーが明示した条件**は、最終投稿はInstagramアプリ、自動配置と簡単な修正で十分、アプリのログイン不要、写真のサーバー送信なし、端末間同期なし。MacBookのCodexで継続開発し、自分のGitHubで管理・デプロイできる形で納品する。

作るのは写真の編集・書き出しまでであり、Instagramの認証やAPI連携ではない。GitHubの開発用認証と、アプリ利用者のログインは別物。

## 2. メインの操作経路

| 段階 | ユーザーの操作 | アプリの責務 |
|---|---|---|
| 選ぶ | iPhoneの写真を複数選択 | ブラウザから渡されたファイルを順次読み込み、端末内で作業用画像に変換。 |
| 自動配置 | 基本的に待つだけ | 縦横比から分割数を提案し、順番を維持して初期レイアウトを表示。 |
| 前処理 | 必要な元写真だけ選択 | 傾き、上下左右の不要部分、中央正方形化を非破壊で調整。回転後も元の縦横フレームを維持し、白場が出ないよう必要最小限を自動拡大。 |
| 微調整 | 必要な写真だけ選択 | 順番、1〜6枚の分割、全体表示／枠いっぱい、位置、拡大、背景を調整。 |
| 組み合わせ | 必要なら隣の写真と組にする | 2写真の並置・重ね合わせを提供。自由配置を必須にしない。 |
| 確認 | 横にスワイプ | つながる表示と、1枚ずつの表示を切り替える。 |
| 書き出す | 書き出しボタンを押す | 1ページずつJPEG/PNGを生成し、連番と保存用一覧を用意。 |
| 保存 | 共有メニューまたは個別保存 | OSにファイルを渡す。実際の写真保存成功はユーザーが確認。 |
| 投稿 | Instagramアプリで複数選択 | 01、02…の順番と、切り抜きを変えないことを案内。自動操作はしない。 |

## 3. 実装で決めた初期値

初期比率は4:5、スタイルは余白なし、配置は「全体を残す」、出力はJPEG。初期状態では横長写真をページの間で独立に切り抜かない。全体表示では写真の形次第で外周に余白ができる。「余白なし」というスタイル名は装飾用の外枠を加えない意味で、全体表示時の比率差による余白まで消すという意味ではない。

写真の縦横比を `a = width / height`、投稿1枚の比率を `r` とする。`a < 1.2` なら1枚、それ以外は `round(a / r)` を2〜6に制限して提案する。合計が20枚を超えたら、分割数の多い組から減らす。写真を黙って捨てない。追加時に既存写真の分割数まで変わった場合はお知らせを表示する。

これは画像の内容を理解するAIではない。自動の顔認識・主題抽出・色合わせ・最適な写真ペアの選定はv1には含めない。写真を一組にする操作はユーザーが行う。

比率を変えたときは手動で決めた分割数を保持する。分割数まで提案し直すときは「おまかせ」を使い、手動調整がリセットされることを確認する。

## 4. 機能要件

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| F01 | 複数写真入力 | JPEG/PNG/WebPの静止画を読み込める。HEICはブラウザの対応範囲で受け付ける。不適合ファイルは理由を表示する。 |
| F02 | 自動配置 | 20写真以内なら、全写真を保って20出力以内の初期配置ができる。ブラウザから受け取った順番を保つ。 |
| F03 | つながる分割 | 1写真が2ページにまたがる場合、同じ拡大率・位置・クリップ枠を共有し、内部境界に意図しない空白を挿入しない。 |
| F04 | 修正 | 分割数・順番・収め方・拡大・縦横位置・背景を変更できる。解除や元に戻す経路がある。 |
| F05 | 2写真の組 | 隣接する単独写真を一組にし、並べる／重ねるを変更できる。2写真を別々に戻せる。 |
| F06 | 統一出力 | 4:5は1080×1350、3:4は1080×1440、1:1は1080×1080。1投稿内の全画像を同サイズにする。 |
| F07 | 装飾混入防止 | プレビューの番号・破線・ボタン・ブランドを画像に焼き込まない。透かしなし。 |
| F08 | 保存 | 書き出し済みのFilesに対して対応確認し、クリック直後に共有。キャンセルしても生成画像を残す。個別保存とZIPを用意する。 |
| F09 | 投稿順 | ファイル名に01、02…を含め、保存用一覧に同じ順番を表示する。OSの写真一覧の順番は保証しない。 |
| F10 | ローカル下書き | 450msの変更待ちのあと、このブラウザに1件保存。読み込み時に復元。失敗を表示し、任意のファイル持ち出しも提供。 |
| F11 | データ削除 | このブラウザ内の編集写真・設定を明示操作で削除。元の写真やすでに保存した出力は削除しない。 |
| F12 | モバイル操作 | 390px幅でページ全体に横はみ出しがない。写真設定とプレビュー間の移動ボタンを用意。ドラッグを必須にしない。 |
| F13 | 持ち帰り | ソース、ビルドスクリプト、テスト、引き継ぎ資料、公開ワークフローを含む。 |
| F14 | 元写真の前処理 | 写真ごとに-180〜180度を0.1度刻みのスライダーと±0.1度ボタンで調整し、上下左右のトリミング、中央正方形化ができる。回転後も元の縦横フレームを維持し、四隅に白場を出さない最小倍率へ自動拡大する。元ファイルは変更しない。 |
| F15 | 異なる見せ方の混在 | 1つの統一出力比率の中に、横写真の2ページ連結と、正方形写真を中央配置した上下余白付き単体ページを順番どおり混在できる。 |

## 5. 非機能要件

写真、ファイル名、サムネイル、下書きをサーバーに送らない。実行時に外部CDN、Webフォント、計測サービス、外部AIを呼ばない。必要な通信は静的なアプリ本体の取得・更新だけ。ユーザー自身が共有を選んだ後の送信先はOSの共有先であり、選択はユーザーに委ねる。

画像の入力と出力は1枚ずつ処理する。20枚ぶんの巨大な本番Canvasを作らず、描画用のデコード画像は最大2つのキャッシュに抑える。元ファイルは改変しない。

作業用画像は長辺4096px、約8MP以内。入力1枚40MB、デコード後の元画像100MPを上限にするが、デコード自体が端末のメモリ制限で失敗する可能性はある。写真枚数上限は実機の処理能力を保証する数ではない。

下書きアーカイブは100MBまで。安全な相対パス、CRC、写真の参照整合性、配置値、JPEGのデコード後サイズを検証する。圧縮ZIPや汎用的な他社プロジェクトのインポートは対象外。

## 6. 対象外

ログイン、共有アルバム、クラウド保存、自動同期、Instagramの自動投稿、予約投稿、文章生成、AI被写体認識、動画、Live Photoの動画部分、RAW現像、無制限の写真数、自由な文字入れ・全要素のドラッグ、一般向けマルチプロジェクト管理はv1では行わない。

複数タブの同時編集にも対応しない。同じ下書きは1つのタブで編集する。OSの写真・ファイル・クラウド同期設定までは制御しない。

## 7. 完了判定

実装上の機能確認と、自動テストの結果は `TESTING.md` に分けて記載する。納品時点で、iPhoneのネイティブ共有メニュー・HEICの実ファイル・Instagramでの投稿・GitHub上の公開は未確認。**この4点を未確認のまま「iPhoneで本番動作保証済み」と表示しない。**

リリース前の最重要受け入れ試験は、ユーザーのiPhoneで横長写真1枚を選び、2枚に分け、写真アプリへ保存し、Instagramで01→02の順に選んで、つながりを確認できること。
